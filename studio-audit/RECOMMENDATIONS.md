# Recommendations

## Immediate

**Publish and review this audit before deleting additional architecture.**

Protects canonical content and asset references.

## Immediate

**Define a single flat-background record/manifest contract before retiring environment layer records.**

Current generators and API still represent multi-layer assets.

## Immediate

**Decide Unity ownership for Planet Detail sprite placement and freeze only semantic asset keys in Studio.**

PSD slicing contains presentation layout metadata.

## Next

**Consolidate generator inputs around canonical record IDs and source-master manifests.**

Reduces prompt and generator overlap.

## Next

**Add an automated route screenshot harness to the audit process.**

This audit could not capture live pages without browser automation.

## Later

**Deprecate historic map route names behind redirects after link inventory review.**

Current navigation is library-oriented while some URLs are map-oriented.

## Do not change yet

**Six engine exporters.**

Static routes are present, but runtime payload compatibility was not executed in this audit.


## Direct answers

- **What should move to Unity?** Screen composition, responsive layout, screen coordinates, animation, interaction, gameplay state, and player state.
- **What should remain Studio-only?** Canonical record identity, prompt history, source-master tracking, approval state, asset manifests, validation, and sanitized publication.
- **What must be preserved before removal?** Approved background assets, semantic keys, source-master links, prompt lineage, asset checksums, runtime references, and any active manifest IDs.
- **Highest risk systems:** multi-layer environment persistence, PSD screen slicing as layout ownership, and divergence between fallback/local/live data sources.
